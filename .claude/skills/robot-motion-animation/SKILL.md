# 로봇 동작 애니메이션

4대가 한 화면에 나란히 돌아가므로, 각각 예쁜 것보다 **같은 그림책의 네 페이지**처럼 보이는 것이 중요하다. 아래 규격을 벗어나면 통일성이 깨진다.

## 무대 규격 (모든 로봇 동일)
- SVG `viewBox="0 0 400 300"`, 바닥선 `y=250` (가로 전체, 점선 2px).
- 로봇 크기: 바운딩 박스 높이 120~160, 가로 중심 `x=200`.
- 이동 동작은 무대 안에서만(±90px) 왕복하고 끝날 때 중심으로 돌아온다. 다음 동작이 같은 자세에서 시작하게 하기 위해서다.
- 회전(좌/우 회전)은 옆모습에서 표현이 안 되므로 위에서 본 작은 미니맵 원(오른쪽 위 `cx=350 cy=50 r=28`)에 방향 화살표를 같이 돌린다. 4대 공통 장치로 쓴다. 예외: 좌우 균형이 핵심인 로봇(바이크)은 이 원 안에 뒤에서 본 모습(기울기)을 그리고, 진행 방향은 원 테두리의 작은 삼각형으로 표시한다. 위치·크기는 같게 유지한다.
- 인벤토리에서 unknown인 움직임(예: 제자리 회전인지 곡선 이동인지)은 과장하지 말고 가장 보수적으로(작은 각도, 방향 표시만) 그린다. 균형·보정 동작은 실제 제어 범위 안의 작은 각도(수 도)로 그린다.

## 디자인 토큰 (`hub/hub.css`의 `:root`에 정의, 모듈은 CSS 변수만 사용)
- 선: `--line: #1f2937`, 굵기 3, `stroke-linejoin: round`. 면: `--fill: #ffffff`, 보조면 `--fill-2: #e5e7eb`.
- 로봇 강조색(작은 부품 1~2곳에만): `--c-smars #2563eb`, `--c-ottobot #f59e0b`, `--c-robotdog #10b981`, `--c-bike #ef4444`.
- 효과(소리, LED, 센서파): `--fx: currentColor` 점선 호. 음표 ♪는 `<text>`로.
- 다크 모드에서는 `--line`, `--fill`, `--fill-2`(예: #374151, 보조면이 밝은 선과 구분되도록)가 바뀐다. 모듈에 색을 하드코딩하지 않는다.

## 모듈 작성법
- 규격은 `hub-shell` 스킬의 「모듈 등록 규격」. `play(t)`는 **t만 보고** 자세를 계산하는 순수 함수로 짠다(이전 프레임 상태를 쓰지 않음). 그래야 셸이 아무 시점에서 멈추거나 건너뛰어도 그림이 깨지지 않는다.
- 관절은 `<g transform="rotate(a cx cy)">` 중첩으로 만든다. 각도는 `Math.sin(2π·t·n)` 같은 주기 함수나 키프레임 보간(`lerp`, ease-in-out)으로 계산한다.
- 동작 길이 `ms`: 2000~3200. 동작 사이 자세는 "기본 자세".
- 동작 하나당 자막은 2~6자 한국어(예: 전진, 문워크, 앉기, 균형 잡기).

## 대표 동작 고르기
1. 인벤토리 `motions` 중에서만 고른다.
2. 4~6개. 이동(전진/후진/회전) 1~2개 + 그 로봇만의 특징 동작 2~4개 순서로 배치한다. 관람자가 로봇의 차이를 느끼는 것은 특징 동작이기 때문이다.
3. 소리·LED·센서 반응처럼 몸이 안 움직이는 기능은 효과(음표, 빛, 초음파 호)로 표현하되 최대 1개.
4. 고른 이유와 뺀 동작을 `_workspace/03_animator_motions.md`에 적는다.

로봇별 외형과 알려진 동작 출발점은 `references/robots.md`를 읽는다(인벤토리와 다르면 인벤토리를 따른다).

## 자체 점검
- 4개 모듈을 한 페이지에 띄워 캡처했을 때 선 굵기·바닥선·로봇 크기가 맞는가
- 모든 동작이 `t=0`과 `t=1`에서 기본 자세인가(이어질 때 튀지 않음)
- 외부 파일·라이브러리 참조 0건
